Mechanism Transparency · 机制透明度文档

AI 如何懂我：
个人认知档案的机制架构

一份给本人审查的公开文档：当 AI 协作者声称"越用越懂你"，背后必须有一套可检查、可纠错、可回滚的机制。本文把这套机制完整摊开——包括它现在做不到什么。

状态：L1 已运行 · L2/L3 设计定稿 · 建设中

01问题：三块真实的短板

这不是一个假想中的问题。以下三条全部来自实际运行中发现的事实：

发现事实含义
记忆超载 用户档案文件已达 3,249 字符，而每会话注入预算只有 1,375 字符，超出 2.4 倍 "往一个文件里堆"的路线已到头。继续堆要么被截断，要么挤掉别的记忆
克隆泄漏 克隆一个新协作者环境时，全部个人记忆（含敏感内容）被连带复制。事后靠人工审查发现并清除 个人数据没有边界约束时，复制操作就是泄漏通道
风格 ≠ 思维 文字风格检查（禁用词、排版纪律）可以执行，但一篇文章"像不像我"取决于思维框架，不取决于用词 需要单独一层记录"怎么想"，与"怎么写"严格分开
结论：懂一个人 = 结构化档案 × 按需读取 × 持续策展。不存在"AI 自动越来越懂你"的魔法——任何声称如此的系统，要么在偷偷收集你看不到的数据，要么在夸大。

02三层架构

L1常驻层 · USER.md

任何对话都加载的身份内核。只放每句话都用得上的事实：身份、对话态度、隐私红线、协作方式。

硬上限 1,375 字符 · 每会话注入 · 超限即失效面扩大

L2按需层 · 认知档案（分卷技能）

按任务相关性加载的结构化档案，用技能系统的 references 机制实现——只在任务匹配时读入，无预算压力。规划分卷：

  • writing-voice.md — 文风、标题规约、禁用词（管"怎么写"）
  • thinking-style.md — 思维框架、判断习惯、类比体系（管"怎么想"）
  • values-faith.md — 价值观与信仰话题的对话边界
  • collab-style.md — 讨论方式：全展开、指盲区、不迎合不抬杠
  • work-context.md — 行业经历细节与项目构想全貌

无硬上限 · 按相关性加载 · 明文 markdown

L3沉淀管道 · 纠正入库流程

"越用越懂你"的真实机制：对话中发现的用户纠正与偏好 → 以 diff 形式提议 → 用户审核 → 入库并版本化。agent 无权单方面写入 L2。

每次更新 = 一次用户审核 · git 版本化 · 可回滚

L1 与 L2 的分界规则

判断一个问题：这句话是不是每段对话都用得上？是 → L1（但要付出预算）；只在特定任务类型用得上（写文章、信仰讨论、行业项目）→ L2。L1 里放不下的，不是删掉，是迁移到对应分卷并在 L1 留一行指针。

03一次纠正的完整旅程

共鸣不是文件堆出来的，是一个循环磨出来的。以一个真实发生的纠正为例：

用户在讨论中发现 AI 的一个表述不准确（例：把"装了某技能"当成了"用过某技能"），当场指出。
AI确认错误，复述正确的边界（"装了不等于用了"），并说明这个误判是怎么发生的。
AI对话结束时提出档案更新建议（diff 形式）："建议在 collab-style.md 增加：陈述'用户在用 X'之前，先核实触发记录。"
用户审核：同意 / 修改措辞 / 拒绝。拒绝则不入库，对话中的道歉不算数。
系统入库并 git commit——这条纠正从此带版本号：谁改的、何时改的、改之前是什么，全部可追溯。
验证下次同类任务中，AI 的行为应当不同。行为不变 = 入库无效，需要在下次纠正时追查原因。
这个闭环的关键性质：AI 对自己的每次"懂你"主张都负有举证责任。"我说我记住了"不是证据，下次会话里行为改变才是。

04保证与纠错机制

4.1 你凭什么信它没乱记

  • 明文原则：所有档案是用户自己磁盘上的 markdown 文件，随时可打开阅读。没有隐藏存储、没有云端黑箱。
  • 审核入库：L2/L3 的每次变更以 diff 提议，用户批准才生效。AI 单方面写入视为违规。
  • 版本化：档案目录纳入 git。任何一条记录的来龙去脉（哪次对话、什么纠正、谁批准）可回溯。
  • 最小化：只记录可复用的框架与边界，不记录事实性隐私（地址、账号、联系方式在红线清单内，永不入档）。

4.2 防回音壁——你担心的信息茧房

这是整个设计里最重要的一节。认知镜像如果做过了头，就变成附和机器：AI 只会复述你的立场，你只听到自己的回声。四道防线：

防线机制违反信号
记录框架，不记录结论 thinking-style 卷只写"用户如何分析问题"（例：先问本质再问可行性、务实闭环压倒概念完备），永不记录"用户认为 X 是对的"这类结论 档案里出现站队性表述
镜像的反面责任 知道用户怎么想之后，义务是指出容易不想什么——思维框架同时也是思维盲区的来源 连续三次讨论无任何异议或补充视角
强制 steelman 深度讨论的决策性结论，AI 必须先给出反方最强论证再表态。给不出 = 讨论不充分 结论出现在反方论证之前
宪法条款 用户档案中已写入常驻规则："不迎合不抬杠，客观中立；不要因为怕迎合就故意反对——该认可就认可"† —

† 这条的原文来自用户本人此前的纠正，经审核入库。它本身就是 L3 流程运转的产物。

诚实的失效模式：防回音壁防的是机制性附和，防不了模型本身的迎合倾向。后者靠用户保持抽查习惯（故意问一个自己可能错的问题，看 AI 敢不敢反驳）来监督。这个抽查建议写进了协作惯例。

05执行层分级：哪些是管道，哪些是判断

本页 §02–04 描述的机制里，有一部分当前落在 prompt 层（Markdown 指令影响 AI 的倾向，但不保证行为）。prompt 是概率性管道：适合发散与判断类任务，不适合"必须发生/必须不发生"的流程。因此每条机制都要明确它处于哪一级执行层，并给出升级路径：

执行层强度已有实例局限
prompt（Markdown 指令）倾向影响，概率遵守文风规约、"不迎合"条款、L3 提议习惯忙起来会漏、会跳过
config（配置开关）会话级强制verify_on_stop、profile 工具裁剪、记忆字符上限只覆盖框架已内置的检查项
hook（进程级脚本）物理强制pre-commit 测试门——测试不绿，commit 进不去只拦截可脚本化的检查
cron（机器触发）时间强制定时任务、每日日报到点就跑，不判断对错

三个待建的硬化构件

构件把什么从 prompt 层升级状态
L3 审计 cron"对话结尾提议档案更新"的习惯 → 每周机器触发审计：对比纠正事件数 vs 档案入库数，差值即待审清单，推给用户。漏掉变成看得见的告警✅ 已建（2026-11-20）
档案审批门"用户审核才入库"的约定 → 档案目录单独建仓，pre-commit 钩子要求每条变更携带审核痕迹；git 历史使事后不可抵赖待建
L1 预算卫兵"定期检查记忆超载"的自觉 → 字符数脚本（wc -c vs 上限）挂 cron，超限必然报数待建

设计原则：硬化应该跟着被验证的不变量走

不是所有流程都该管道化，过度硬化有三个代价：其一，僵化——把今天还没想清楚的规则焊死，系统就会失去随认知演化的能力（正如把错误的配方下放产线，损失是批量的）；其二，假确定性——管道给你"流程跑了"的证据，但流程之外最大的风险是方向性判断错误，没有任何 hook 能拦住一个错误的决定；其三，维护税——每个管道都需要人维护，管道越多，维护挤占思考。

分界线：检查可以写成代码的，写代码；需要判断的，写 prompt，但配一个让偏差可见的机制（审计/告警），而不是假装它已经被强制。新流程先在软层试点，验证为不变量后再硬化——如同制造业配方须经现场验证后才下放执行系统。

06做不到的事（诚实清单）

  • 不会隐式画像：没有你看不到的暗中积累。所有"懂你"的载体就是那几个文件。
  • 文件不能让模型"变成你"：档案校准的是输出，不是模型本身。换底层模型后，档案还在，共鸣精度需要重新校准一轮。
  • 上下文压缩会丢细节：长会话压缩是摘要过程。所以关键事实和纠正必须落文件，不能只活在对话里。
  • "了解程度"有上限：档案覆盖的是被对话触发过的模式。没聊到的领域，AI 对你的认知是空白——这是特性（不臆测）也是局限（不主动）。
  • L3 依赖用户参与：你不审核，管道就停。整个系统的保鲜度 = 用户愿意投入的审核时间。

08已经发生过的三个真实案例

  1. 称呼纠正入库：早期对话中 AI 对用户背景的一次表述不准确，用户纠正后以一条记忆入库（含"倾向中性描述"的边界说明），此后所有会话生效。这是 L3 闭环的第一次实跑。
  2. "装了 ≠ 用了"误判：AI 把技能目录里存在的捆绑技能当成了用户的实践成果来引用，被用户当场否认（"我好像从来没有用过"）。AI 撤回结论并修正了推断纪律：引用用户行为前先查触发记录。
  3. 克隆泄漏发现：为新协作者环境做克隆时，AI 主动审查发现全部个人记忆被连带复制（含用户档案与私密记忆），当场清除并重置，用户档案零改动。

三个案例分别是：纠正入库的建立、纠错的强度（用户推翻 AI 结论，AI 接受并修正）、边界的自检。它们不代表系统完美——第 2 个案例本身就是 AI 犯的错——但代表纠错循环真的在转。

本页的最终判断标准不在本页里，在日常使用中：AI 是否减少了对同一件事的重复解释？被纠正后行为是否真的改变？它给出的反对意见是否让你不舒服但事后证明有价值？——下一个任务是唯一的测试。
